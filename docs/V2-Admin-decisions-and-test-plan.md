# Admin 已確認規格與開發驗收清單

更新：2026-11-17（Asia/Taipei）。來源：使用者於本次對話逐項採納的副本、卡套與撤銷決策。

本文件是後續實作與測試依據，不表示功能已完成、測試已通過或整頁設計已核准。未修改 UI、Migration、後端或正式資料。Release-03 version 19 驗收仍為既有基準，不重做登入驗收。

## 範圍與接續

- 本輪第一版：R08／R09 及相關頁面的已確認規則；產品每包張數鎖定、需求備註獨立編輯、按適用副本計算需求、封存排除、兩層不足提示。副本規則影響 R02／R04／R05／R06／R09，須核對並一致實作。
- 後續獨立階段：撤銷套用所需資料庫遷移、後端、帳務與 UI，與本輪分開上線。
- 尚待設計：R08 產品分頁等逐頁布局；本文件不取代逐頁設計確認門檻，不授權部署。
- 所有下列測試皆為「待執行」。實作時依風險落成單元／SQL 整合／瀏覽器驗收；資料遷移與帳務必須在隔離資料庫驗證，不自行建立正式測試資料。

## 2. 產品、需求與不足計算

| ID | 已確認規格／應驗收情境 |
| --- | --- |
| SLV-01 | 產品有交易或套用歷史後，尺寸與每包張數唯讀；品牌、名稱、備註可改。尺寸錯誤停用舊產品並新增，不改寫歷史換算。現行只有尺寸受交易限制，每包張數仍可改，須補齊。 |
| SLV-02 | 停用表示不可再套用；排除可用庫存，尺寸另列「停用產品另有庫存 N 張」。單純停售但仍要使用餘量，保持啟用。產品庫存按產品交易記帳，尺寸合計僅為概況。 |
| SLV-03 | 建立需求／關聯不扣庫存；確認套用與負數 USE 交易同時完成，沒有已套用待扣帳狀態。文案「確認本次使用尚未登錄扣帳，送出後立即扣庫存」。不得再從帳面餘額減一次已套用量。 |
| SLV-04 | 需求張數是每個適用副本各需的量；指定副本只計該副本，未指定則按適用副本展開。例：每副本 100 張、兩個適用副本＝200 張，不能直接加總需求資料列當總需求。 |
| SLV-05 | 待套用量逐適用副本、逐需求計算為需求量減有效已套用量，再按尺寸加總。在藏／借出計入；售出／送出／遺失排除；未知不納入確定需求且提示可能漏計；封存收藏全排除。異常負數或無法可靠判定不可包裝為正常零需求。 |
| SLV-06 | 全域缺口＝max(0，全域該尺寸待套用量－該尺寸啟用產品帳面庫存合計)。R08 顯示需求、庫存與缺口張數；Dashboard 顯示「N 種尺寸庫存不足」。 |
| SLV-07 | R02／R04「卡套不足 N 項」：該收藏同尺寸待套用量大於該尺寸啟用產品庫存則計 1 項，同尺寸多需求不重複。此算法不預留／分配庫存，收藏提醒數不可相加作全域結果。兩收藏各需 80、庫存 100：各收藏 0 項，全域缺口 60。 |
| SLV-08 | R09 可提示「此尺寸與其他收藏合計的需求超過庫存」，不新增角標。歷史套用無法對應、組件未確認、未知庫存等詳細資訊只在 R09 提示，不新增 R06／頁首待確認來源；受影響數值不可顯示充足或缺口 0，可顯示「—」。尚未建立庫存不等於零；驗證無交易與明確零餘額的區別。 |
| SLV-09 | 實際套用選產品並檢查該產品庫存，尺寸相符仍可能有厚度／材質差異。需求 100、A/B 各 60 時不可一次從單一產品扣 100，可分次選產品套用；總進度不得超需求。 |
| SLV-10 | 套用要求有效實體 card 組件資格及簽章／版本證據、該副本該組件 inspection_status=checked、副本在藏且未封膜、收藏未封存、啟用同尺寸產品與足夠庫存。整筆標不需清點且沒有有效組件清點依據不可套用，顯示原因；副本整體清點狀態不能取代組件清點。 |
| SLV-11 | 有有效套用時鎖定尺寸、張數、適用副本與組件，但仍可繼續套用剩餘張數；備註可獨立編輯並保存修改紀錄，不需撤銷。須同步調整資料庫整列鎖定限制，驗證備註入口不能繞過核心欄位鎖定。 |
| SLV-12 | 增加需求用新增補充需求；不能把補充需求或手動庫存調整當作修正錯誤套用。需求備註上限 1,000；產品與交易備註各 1,000。 |
| SLV-13 | 引用數分為有效需求筆數與歷史套用筆數。有效需求至少排除封存收藏；筆數不是按副本展開後的張數。歷史套用包含已撤銷歷史但須區分狀態，不能用歷史筆數推算目前進度。 |
| SLV-14 | 第一版未提供撤銷，確認前提示「確認後會立即扣庫存，套用紀錄目前無法撤銷；需求的尺寸、張數、適用副本與組件將鎖定。請先核對產品、副本與張數。」不得顯示未上線的撤銷能力。 |

## 3. 撤銷套用：後續獨立實作階段

定位為更正登錄；實際耗損／拆除另行設計，不併入本次。下列均為已確認規格、尚未實作／測試。

| ID | 已確認規格／應驗收情境 |
| --- | --- |
| REV-01 | R09 單筆副本套用紀錄提供「撤銷這次套用」，不從需求層級操作；一次撤銷整筆，不部分撤銷。原因選項：登錄錯誤、選錯產品、選錯副本、張數錯誤、其他；其他必填說明。 |
| REV-02 | 不修改或刪除原套用／使用交易；新增撤銷紀錄判定已撤銷，保存操作時間、原因、操作人與回補選擇。原紀錄與撤銷歷史可查；私人操作資料不公開。資料表／欄位與交易關聯於實作設計決定。 |
| REV-03 | 退回／不退回必須明確選擇，無預選。退回固定為原產品、原張數，不可換產品或改量；停用產品也不能造成無法更正帳務，回補後仍不列可用庫存。 |
| REV-04 | 選退回：新增對應回補交易，原使用交易保持不變。不退回：庫存不變，原扣帳保留；明示「之後重新套用會再次扣庫存」。 |
| REV-05 | 系統無法自動判斷無關聯的既有手動退回。明示「如果你已在庫存交易中手動退回，請選不退回，避免重複回補」，不可宣稱已有自動偵測／阻擋。 |
| REV-06 | 撤銷紀錄與選擇的回補交易原子提交；任一步失敗全部回滾。測試雙擊、重送、併發撤銷、相同冪等鍵相同／不同內容及失敗後重試，不能重複回補。每筆套用最多撤銷一次、撤銷不可取消；重新套用建立新紀錄，不另設任意循環次數上限。 |
| REV-07 | 所有已套用量、剩餘需求、收藏／全域不足、產品實際套用與公開查詢只採有效未撤銷套用。歷史統計保留原使用及回補交易；撤銷不回補案例尤其須驗證進度減少但帳面餘額不變。 |
| REV-08 | 需求沒有任何有效套用才解鎖核心欄位；剩一筆有效套用仍鎖定，但可套用剩餘量。其他副本的有效套用也會阻止整筆需求解鎖。保留未對應歷史造成的保守鎖定，不以此次撤銷繞過。 |
| REV-09 | 隔離資料庫驗證舊資料遷移、既有不可變限制、外鍵／唯一限制、交易型別與關聯、權限／併發及公開資料邊界；遷移不能改寫原交易與套用歷史。實作前準備可審查的 Migration 與驗證結果，正式部署仍依另外確認的流程。 |

## 7. R09 需求表單尺寸選擇建議與程式核對

2026-11-17：使用者提出 A／B，本輪建議採 A 的既有尺寸選單，但允許選全部既有獨立尺寸（含沒有產品的歷史尺寸），尚待使用者確認此細節。新增全新尺寸沿用 R08 建立產品入口，不在需求表單自由輸入；不為保留既有需求而要求建立虛構產品。

- 程式事實：v2_sleeve_sizes 是獨立表；產品與需求各自以 size_id 外鍵引用。尺寸為 0.1 mm 整數儲存，寬高組合唯一；63 × 88 與 63.5 × 88 是不同尺寸，不應近似自動合併。目前 R09 讀取全部既有尺寸，不限有產品者；後端只要求尺寸存在。
- 建議驗收：可搜尋尺寸且顯示 mm；有啟用產品／僅停用產品／無產品清楚區分；無產品選用後仍採既定資料不完整規則。由新增產品返回需求表單時保留未儲存資料並選取新尺寸。
- 表單方向：每個適用副本需要 N 張，依在藏／借出展開顯示 N × M = T；全部副本不是固定快照，新副本符合資格後也適用，提示其效果。未知另提示可能漏計；售出／送出／遺失不列新增選項，既有指定歷史副本仍應可辨識，不能靜默改指派。
- 名稱／說明現況是同一個 notes 欄位、上限 1,000，非兩個獨立欄位。可選新指派組件僅合格 card；既有不合格歷史引用唯讀辨識，不自動清空。無合格組件時可指向 R07 證據及 R06 管理入口；是否仍可儲存未指派需求沿用現況，尚未決定強制組件必填。
