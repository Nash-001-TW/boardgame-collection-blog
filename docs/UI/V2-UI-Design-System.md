## 2. 設計原則（依優先順序）

1. **效率與清楚優先**：日常管理動作最多兩次點擊可達；數字、狀態、錯誤一眼可讀。視覺裝飾不得擠壓資訊或增加操作步驟。
2. **冒險貓咪是品牌識別**：頁首橫幅與各功能的貓咪插畫是主要識別元素，不是可隨意移除的裝飾；但插畫一律不承載資訊（資訊必須同時以文字呈現）。
3. **一致**：全部 Admin 頁使用同一套 token、元件與導覽，不再各頁自定樣式。
4. **失敗關閉與誠實**：狀態不明時顯示「—」或「無法取得」，不可顯示成 0 或「正常」（沿用既有 SLV-08 等規則）。
5. **無障礙不打折**：沿用 web-design-guidelines 審查結論（第 9 節）。

### 3.3 間距、圓角、陰影

- 間距階：4／8／12／16／20／24／32／40 px（`--space-1`～`--space-8`）。卡片內距 20–24px，卡片間距 16–24px。

- 焦點：`--focus-ring: 3px solid #E78B40`，`outline-offset: 3px`（沿用公開網站 `--cat-orange`，品牌一致）。

## 4. 版面骨架（App Shell）

### 4.1 桌面（≥ 1100px）

```
┌──────────────┬──────────────────────────────────────────────┐
│ 品牌區        │ 頁首橫幅（四貓插畫，見 4.4）                 │
│ 🐾 桌遊收藏…  ├──────────────────────────────────────────────┤
│ BOARD GAME…  │ 頁面標題列：圖示＋H1＋副標｜麵包屑／頁面操作 │
├──────────────┤──────────────────────────────────────────────┤
│ 側欄導覽      │ 內容區（max-width 1440px，左右內距 24–32px） │
│ （固定、可捲） │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- 側欄寬 260px，`position: sticky; top: 0; height: 100vh; overflow-y: auto`。
- 導覽群組可收合（`<button aria-expanded>`），目前頁所在群組預設展開；目前項目用 `aria-current="page"` 加紫色淺底與左側強調。
- 頁面標題列不固定（避免遮擋焦點元素）；需要固定的操作列（例如編輯頁儲存）沿用現有 `editor-heading` 並設定 `scroll-padding-top`。

### 4.2 平板（768–1099px）

側欄收成可展開的抽屜（同手機），內容區滿版。

### 4.3 手機（< 768px）

- 頂部 App Bar：☰ 選單按鈕（`aria-label`＋`aria-expanded`）＋品牌名＋必要時的頁面操作。
- 側欄改為左側抽屜：`<dialog>` 或 `inert` 背景，`overscroll-behavior: contain`，Esc 關閉並把焦點還給 ☰。
- 頁首橫幅依 D1（已採納）：R01 顯示 72px 裁切版，取畫面中下方（盔甲與道具，`object-position: center 62%`）；其他頁不顯示。

### 4.4 頁首橫幅

- **出現範圍（D1，2026-11-23 已採納）**：
  - 桌面與平板：**只有 R01 管理工作台**顯示完整橫幅（依寬度等比，不裁切）；其他 Admin 頁面**不顯示**橫幅，品牌由側欄爪印標誌與配色延續。
  - 手機：R01 使用 72px 裁切版，取中下方（盔甲、道具），`object-fit: cover; object-position: center 62%`；其他頁不顯示。
  - 公開網站「關於我」等非目錄頁維持現行完整橫幅，不受本項影響。
  - 使用者看過 72px 裁切比較後，決定桌面不採用裁切。
- 使用現有 `public/images/cat-adventure-banner.png`（2172×724）作為來源，**但須先壓縮**：輸出 WebP，桌面 1600w、手機 800w，以 `srcset` 提供，目標單張 ≤ 250KB。
- `alt` 為空字串並 `aria-hidden`（純品牌裝飾，頁面標題由 H1 提供）。
- 一律附 `width`／`height` 防止版面跳動。

## 6. 共用元件規格

以下元件全部放在共用樣式（建議新檔 `src/styles/admin-theme.css` 定義 token 與元件），各頁不得重新定義相同元件。

| 元件 | 規格要點 |
| --- | --- |
| **頁面標題列** | 線條圖示（32px，`aria-hidden`）＋H1＋一行副標；右側放「更新時間」與次要操作（如「重新整理」）或麵包屑。 |
| **按鈕** | 高度 44px（觸控目標），圓角 12px。`primary`：紫底白字；`secondary`：羊皮紙底＋`--border-strong`；`danger`：白底紅框紅字；`ghost`：透明。皆有 hover（加深一階）、`:focus-visible` 焦點環、`disabled`（50% 不透明＋`cursor: not-allowed`）。動作進行中顯示 spinner 並保留按鈕寬度。只有圖示的按鈕必須有 `aria-label`。 |
| **快捷操作磚** | 一列 5 個（桌面）／2 欄（手機）。每磚＝圖示＋動詞開頭標籤＋右下淡色爪印浮水印（`aria-hidden`）。以 `<a>` 實作（導向頁面），底色依功能分類用 `*-soft` 色。 |
| **警示橫幅** | 左側語意圖示＋標題＋一句說明＋「查看詳情 ›」連結；底色 `--danger-soft`／`--warning-soft`。資料無法取得時顯示「無法取得」而非隱藏。 |
| **統計卡** | 圓形圖示徽章＋小標＋大數字（`tabular-nums`、`Intl.NumberFormat`）＋次要說明（例如百分比）；右下角插畫浮水印（`aria-hidden`，透明度 ≤ 30%）。數字不可得時顯示「—」並附 `sr-only` 說明。 |
| **狀況清單卡** | 標題＋鍵值列（左標籤、右數字）；需注意的數字改用計數徽章（紅＝異常、黃＝待處理、灰＝資訊）。 |
| **計數徽章／狀態膠囊** | 膠囊圓角、圖示＋文字。狀態對照採 R02 設計圖例：異常（缺件、卡套庫存不足）／待確認（尚未清點）／正常（清點完成，無問題）／不適用（願望清單、預購中）。計算規則以既有 R06／R09 決策為準。 |
| **分頁籤（Tabs）** | 收藏詳細頁使用。`role="tablist"`，方向鍵切換，目前分頁紫底白字；分頁上可帶計數徽章（紅＝異常數、灰＝待確認數）。分頁狀態寫入網址。 |
| **表格** | 表頭 `--bg-surface-sunken`；列高 ≥ 64px；封面縮圖 56×74（固定寬高、`loading="lazy"`、失敗時顯示文字佔位）；可排序欄用 `<button>` 並設 `aria-sort`；手機版改為卡片列表。 |
| **篩選列** | 搜尋框（`type="search"`、`autocomplete="off"`）＋下拉篩選＋「更多篩選」；下方「已套用條件」以可移除的膠囊顯示並提供「清除全部」；所有條件寫入網址。 |
| **分頁器** | 首頁／上一頁／頁碼／…／末頁／下一頁；目前頁紫底並 `aria-current="page"`；附「顯示 1–20 筆，共 N 筆」。 |
| **數量步進器** | `−`［數字輸入］`+`，三者各 ≥ 44px；輸入框 `inputmode="numeric"`；未儲存時顯示草稿狀態（鉛筆圖示），儲存中、儲存失敗（可重試）各有明確狀態。 |
| **確認彈窗** | 用原生 `<dialog>`；標題說明動作，內文列出「將被覆蓋／影響的項目」，主要按鈕寫出具體動作與數量（例如「確認並套用（3 項）」），次要為「取消」。破壞性或不可逆動作一律經此彈窗。 |
| **批次結果回報** | 成功／失敗逐項列出；失敗項提供「重試」；標題寫「部分完成：成功 2、失敗 1」。 |

| **待處理項目列表** | 語意圖示＋描述＋計數徽章＋前往箭頭；整列是連結。 |

## 7. 插畫系統

插畫是品牌識別的核心，但**目前 repo 只有一張橫幅插畫**，其餘需要新素材。

| 類別 | 用途 | 現況 |
| --- | --- | --- |
| 頁首橫幅 | 全站品牌（四貓：黑貓盜賊、白貓法師、三花騎士、橘貓戰士） | 已有，需壓縮 |
| 功能縮圖 | 收藏、卡套、組件、採購、遊戲資料、待處理等功能卡與側欄群組 | **缺**，需新製 |
| 空狀態插畫 | 尚無副本（開箱）、願望清單（星星卷軸）、預購中（日曆卷軸）、不需要清點 | **缺**，需新製 |
| 卡片浮水印 | 爪印、骰子、卡牌、拼圖、書本、貓剪影 | 可用 SVG 線稿實作（不需點陣圖） |

**素材規格**（供製作者依循）：

- 角色必須是橫幅中的同一組四隻貓，畫風、線條粗細與色調一致。
- 格式：透明背景 WebP（另附 PNG 原檔），功能縮圖 2 倍圖 256×256、空狀態 2 倍圖 480×360；單檔 ≤ 60KB（WebP）。
- 全部視為裝飾：`alt=""`＋`aria-hidden="true"`，旁邊一定要有文字標籤。
- 不可在插畫中放入需要閱讀的文字或數字。

## 9. 無障礙與效率規則（摘要）

沿用 2026-11-23 web-design-guidelines 審查結論：

- 跳至內容連結、正確的標題層級、每頁一個 `<main>`（Admin 目前用 `#editor-content`，保留）。
- 焦點環一律可見；只用 `:focus-visible`；固定元素不得遮住焦點元素（`scroll-padding-top`）。
- 觸控目標 ≥ 44px；表單欄位有 `<label>`、正確 `type`／`inputmode`／`autocomplete`。
- 動畫只用 `transform`／`opacity`，並尊重 `prefers-reduced-motion`；不使用 `transition: all`。
- 數字用 `tabular-nums` 與 `Intl.NumberFormat`；日期用 `Intl.DateTimeFormat`；金額依幣別顯示（沿用「已記錄採購成本」規則，不跨幣別加總）。
- 未儲存變更離開前提醒；破壞性動作需確認。
- 狀態不可只用顏色表達。

## 14. 依功能性質決定呈現方式（**候選**，2026-11-27，DECISION_LOG RELINK-UI-Q155）

來源：使用者提供的外部意見（更換對應遊戲版面討論的第六點），經使用者同意記入，作為之後畫面的方向。這一節仍是**候選**，不是已採納的規格；套用到具體頁面時，仍要依 AGENTS.md §5 逐頁確認。

| 功能性質 | 呈現方式 | 例子 |
| --- | --- | --- |
| 核心資訊 | 直接顯示 | 收藏名稱、對應遊戲、基本資料 |
| 常用的管理操作 | 精簡清單或表格 | 組件清點、卡套需求、採購 |
| 細節 | 展開／收合 | 副本詳細資料、備註 |
| 少用但影響大的變更 | 彈出視窗（`admin-kit-dialog`），先預覽再確認 | 更換對應遊戲、庫存扣帳 |
| 歷史與稽核 | 按需開啟（彈出視窗；需要時再考慮側邊抽屜） | 更換紀錄、庫存交易紀錄 |
| 操作成功 | 短暫提示，自動消失 | 儲存成功、更換成功 |
| 持續存在的異常 | 行內提示 | 庫存不足、數量差異 |

原則：新增功能時，不在頁面底部再加一個大型區塊；入口要靠近它影響的資料。
