## A. 效能與准入容量

兩份 `node:sqlite` 記憶體 DB 先套用 0001～0022 並載入同一份合成資料。候選 DB 在載入後套用 0023，以涵蓋對既有收藏建立世代列的流程。兩邊都驗證有 1,000 筆收藏、3,000 筆副本、10,000 筆組件定義、30,000 筆清點、3,000 筆狀態標籤，並通過外鍵檢查。

成功測試使用分類資料低於上限的獨立 fixture。11,000 列容量案例保留目標的世代及證據，新增其他收藏與組件以單獨驗證全庫計數限制。副本、清點與狀態標籤未計入 `classification_rows`。中位數倍率按工作單門檻評估，改名正好到 2.00 倍，副本編輯 p95 為 2.25 倍。微秒級結果有執行波動，一次成功提交只代表該樣本。

本機 `DatabaseSync` 無網路往返，`sqliteD1` 以本機交易模擬 batch。實際 D1 的 Worker 到資料庫延遲、鎖競爭、服務限制、batch 與跨執行環境一致性皆無量測。這些數字只能用於本次相對比較。

## B. 0023 觸發器錯誤碼

19 種訊息均由 SQLite 實際觸發。重複使用同一訊息的位置也逐一執行，共 48 個 `RAISE(ABORT)` 位置，其中 20 個 `D1_GENERATION_MISSING` 位置透過缺列故障注入覆蓋。表中的 HTTP 是沿現有服務與 handler 靜態核對的結果。「不可達」表示目前產品呼叫端未發出該操作，或前置守衛先拒絕它。

| SQLite 錯誤碼 | 實測觸發操作 | 目前呼叫端與使用者可見回應 |
| --- | --- | --- |
| `D1_INITIAL_MARKER_FORBIDDEN` | 新建定義時傳入操作標記 | 不可達。R06 create 不寫標記欄位 |
| `D1_REVISION_REGRESSION` | 將 definition revision 1 改為 0 | 不可達。R06 edit 與更正提交皆遞增 revision |
| `D1_MARKER_WITHOUT_CHANGE` | 數量相同時改操作標記 | 不可達。R06 edit 不寫標記，提交回執要求數量改變 |
| `D1_CURRENT_OPERATION_REQUIRED` | 無符合的回執時直接改數量 | 不可達。R06 顯式改量在寫入前回 HTTP 409 `D1_QUANTITY_PREVIEW_REQUIRED`。僅提供與資料不同的預期量時，按輸入回 400 `D1_PREVIOUS_QUANTITY_REQUIRED` 或 409 `COMPONENT_STATE_CHANGED` |
| `D1_HISTORY_IMMUTABLE` | 更新或刪除回執 | 不可達。現有服務只有新增及讀取 |
| `D1_HISTORY_EXISTS` | 重插已存在的操作／版次回執 | `commitSharedQuantity` 的交易競爭路徑。相同操作有回執即 `COMMITTED`，其他操作依世代狀態回 `PERMANENTLY_REJECTED`、`D1_CONFIRMATION_SUPERSEDED` 或 `UNKNOWN`。確認提交沒有 HTTP 入口 |
| `D1_QUANTITY_STATE_CHANGED` | 以落後世代／快照插入回執。容量個案則有當前世代與快照，但全庫列數超限 | `commitSharedQuantity` 捕捉 SQL 例外，以回執與世代重新判定。超限實測為 `UNKNOWN`。世代前進可回 `D1_CONFIRMATION_SUPERSEDED` 或 `COLLECTION_ARCHIVED`。確認提交沒有 HTTP 入口 |
| `D1_EXPECTED_ONE_DEFINITION_UPDATE` | 故障注入讓定義更新為零列，回執插入一起中止 | `commitSharedQuantity` 在該異常路徑會回 `UNKNOWN`（世代未前進且無回執）。完整 schema 的正常服務路徑不可達。確認提交沒有 HTTP 入口 |
| `D1_GENERATION_IDENTITY` | 插入不存在收藏的世代、刪世代、改收藏鍵、REPLACE 已用過的收藏 ID | 不可達。服務採自動配置收藏 ID，無改鍵、重用 ID 或寫世代表 API |
| `D1_GENERATION_NOT_MONOTONIC` | 世代一次加 2。既有回歸也觸發整數上限後再加 1 | 可由整數耗盡觸發。一般寫入按入口回收束錯誤，收藏管理 500 `SERVICE_UNAVAILABLE`，副本／狀態標籤及 R06 503 `SERVICE_UNAVAILABLE`。確認提交沒有 HTTP 入口，沒有回執且世代未前進時回 `UNKNOWN` |
| `D1_GENERATION_MISSING` | 故障注入移除世代列，再對收藏、管理、副本、定義、來源、清點與標籤的各受守衛操作寫入 | 完整 schema 正常路徑不可達。缺列時，收藏管理走 500 `SERVICE_UNAVAILABLE`，副本與狀態標籤走 503 `SERVICE_UNAVAILABLE`，R06 寫入走 503 `SERVICE_UNAVAILABLE`。來源表的更新／刪除先被 0017 擋下，測試以本機 fixture 暫時移除前置守衛覆蓋後置分支 |
| `D1_COPY_IDENTITY` | 明確 REPLACE 已有副本 ID | 不可達。副本建立自動配置 ID，編輯採 UPDATE |
| `D1_DEFINITION_IDENTITY` | 明確 REPLACE 已有定義 ID | 不可達。建立使用自動 ID，重送查建立依據 |
| `D1_ARCHIVE_IMMUTABLE` | 清除既有封存時間或刪除已封存管理列 | 不可達。收藏管理先檢查封存狀態，重複封存回 HTTP 409 `ARCHIVED` |
| `D1_MANAGEMENT_IDENTITY` | 跨收藏重用 request key，或修改原列 request key | 現行 SQL 對原 request key 提供重播檢查，更新保留 identity。若新建撞同一 request key，`CollectionV2Writer.create` 重讀原結果，回重播 200 或 409 `IDEMPOTENCY_CONFLICT`。其餘無法重播的儲存異常走 500 `SERVICE_UNAVAILABLE` |
| `D1_COUNT_IDENTITY` | 跨收藏建立清點 | 不可達。R06 count 在寫入 SQL 內確認同收藏，無符合列時回 HTTP 409 `COMPONENT_STATE_CHANGED` |
| `D1_TAG_IDENTITY` | 用既有標籤 ID 插入另一個 condition code | 不可達。`writeCopyCondition` 用自動 ID 並依副本與 condition code 去重 |
| `D1_RELATED_IDENTITY` | 修改副本、定義、清點或標籤的列 ID／關聯身分 | 不可達。現在的服務 UPDATE 保留這些欄位 |
| `D1_LEGACY_MAP_IDENTITY` | 同 ID REPLACE 成其他映射，或更新映射目標 | 不可達。現行 HTTP 無此寫入路徑 |

HTTP 判讀依 [R06 handler](../src/lib/physical-component-admin-api.ts)、[R06 服務](../src/lib/physical-component-management.ts)、[收藏 handler](../src/lib/collection-admin-api.ts)、[收藏寫入服務](../src/lib/collection-v2-management.ts)、[副本 handler](../src/lib/collection-copies-api.ts)、[副本服務](../src/lib/collection-copies.ts)、[副本狀態與採購服務](../src/lib/purchase-admin.ts) 和 [更正提交引擎](../src/lib/shared-quantity-commit.ts)。採購單、明細與分攤的獨立編輯 SQL 不直接寫入 0023 守衛表。

A2 待處理的是超限及可辨識的交易拒絕如何映射至確認 API、重播及過期回應如何落到 HTTP，以及預期外 SQL 例外的可追溯紀錄。遇到不同識別或世代前進時，現有引擎依持久狀態判定結果，SQL 訊息本身未對外暴露。
