## 三、跨頁規則：副本、收藏與卡套【已定稿】

- 庫存按**產品**記帳，需求與扣帳以**張**計；尺寸是彙總維度；產品與需求各自引用獨立的尺寸資料表。
- 建立需求或指派組件不扣庫存；確認套用同時建立負數 USE 交易與套用紀錄，沒有「已套用待扣帳」狀態。
- 在藏、借出計入持有副本數與需求；借出不能清點或套用，保留清點結果，未清點仍列 R06 待確認並說明「借出中，歸還後才能清點」。
- 售出、送出、遺失：排除目前數量、清點與缺件提醒、待套用需求，於 R05「不在藏副本」收合，問題與歷史保留。
- 未知狀態：不納入已確認持有數或確定需求，獨立稱「狀態未知」、提示可能漏計，不混入 R06「待確認」角標。
- 收藏封存優先，其副本全部退出目前數量與需求；狀態變更或封存不刪關聯、不回補卡套；歷史成本、交易、使用保留。
- 至少一個副本且全為售出／送出／遺失，才提示「所有副本均已不在藏」，不自動改收藏狀態；零副本或含未知不適用。
- 語言差異可用副本區分；組件或卡套需求結構不同則分收藏紀錄；新增同款只提示、不強制合併。

## 四、R08 卡套管理【已定稿】

**產品分頁**：桌面表格、手機卡片；欄位為品牌名稱、寬高 mm／厚度／每包張數、帳面餘額、啟停狀態、經算法驗證才提供的套用筆數；操作為編輯、登錄進貨、停用。新增與編輯用列表內展開區。

- 列表與摘要只顯示張，包與換算放交易輸入；交易歷史保留原包數與每包張數快照。
- 無交易顯示「尚未建立」，不是 0；明確零餘額才顯示 0 張；異常負數警示。
- 摘要涵蓋完整篩選範圍，分列啟用庫存與停用產品另有庫存；資料不完整時稱「已知庫存合計」並提示未建立庫存的產品數。
- 預設啟用，可切換停用；搜尋品牌名稱、尺寸下拉，不輸入 ID。
- 新增不直接輸入庫存；儲存後可跳交易登錄。重複的品牌名稱與尺寸提示、不阻擋，提供使用既有產品。
- 有交易或套用歷史後，尺寸與每包張數鎖定並說明引用數；品牌名稱與備註可改。更正尺寸要停用舊產品、新增正確產品。厚度未提供不顯示 0。
- 停用須二次確認，明示不可再套用、餘量不計可用、歷史保留；可重新啟用但不解除歷史鎖定。

**需求與不足算法**：

- 需求量是「每個適用副本各需要 N 張」；未指定副本則按符合狀態的副本展開，指定則僅該副本。每副本每需求待套用量＝需求量－有效已套用量，再按尺寸加總。只計在藏與借出，排除封存；未知提示可能漏計，歷史無法判定不能當正常零。
- 啟用庫存＝該尺寸啟用產品的帳面餘額合計，不再扣已套用量。
- **全域缺口**＝max(0，全域待套用量－啟用庫存)，Dashboard 顯示「N 種尺寸庫存不足」。
- **收藏層**：該收藏某尺寸待套用量超過同尺寸啟用庫存計 1 項，同尺寸不重複；R02／R04 顯示「卡套不足 N 項」。不預留或分配庫存，不能相加當全域結果。例：兩收藏各需 80、庫存 100，各收藏 0 項，全域缺口 60。
- 可分次使用不同產品；每次只須所選產品足夠，總套用不超需求。程式支持累計上限，實作前仍須實測驗證。
- 不新增卡套「待確認」統計來源；受影響數值不能寫充足或 0，可為「—」或已知量加可能漏計。

**尺寸與庫存分頁**：一列一尺寸（寬高、啟用產品數、已知庫存、未套用總需求、缺口、有效需求筆數與歷史套用筆數）。缺口顯示不足 N 張／充足／無需求／—。展開看各產品餘額、需求收藏與副本、停用庫存。無產品但有需求：資料不完整，缺口「—」，提供帶尺寸新增產品入口。有產品但全停用：可用庫存 0，需求完整且大於 0 時計不足。排序：確定不足、資料不完整、其餘依尺寸。固定說明：「尺寸合計僅供概況；每次套用須選一項產品，且該產品庫存須足夠。可分次使用不同產品。」

**庫存交易分頁**：欄位為交易日期、產品、操作、帶正負方向的張數、交易後餘額、原因備註、可抵達的關聯；預設入帳順序最新在前，餘額按完整產品帳的入帳順序計算，篩選、分頁、排序不能重算其定義。手動交易原因必填，預覽新餘額，後端與資料庫阻擋負庫存。類型：OPENING_BALANCE、PURCHASE、RETURN 為增加；USE、DISCARD 為減少；ADJUST 可正負。**第一版移除手動 USE**（UI 與 API 都限制），USE 只由 R09 套用產生；舊手動 USE 保留，不偽造套用關聯。手動退回與報廢原因必填；報廢只扣仍在庫存的卡套。交易不可編刪，更正新增反向調整；**全面資料庫不可變限制延至後續遷移階段**，不能說第一版已強制。

## 五、R09 卡套需求與套用【已定稿】

- 選單入口預設為有待套用需求的收藏清單，順序為不足收藏、資料不完整收藏、其餘；不能只篩確定量大於 0 而藏起未知資料；可搜尋零需求收藏以新增需求。從全域清單或 R04 進入同一收藏內容元件，用可搜尋收藏選擇取代手輸 ID。
- 資格：有效實體 card 及簽章版本證據、該副本該組件已 checked、在藏未封膜、收藏未封存、同尺寸啟用產品且庫存足夠、未超需求、沒有阻擋的未對應歷史。副本整體清點不能取代組件清點。
- 停用操作時明示原因（未清點、借出、未知、資格不符、產品或庫存問題等），不只變灰。
- 套用選同尺寸啟用產品並顯示餘額；預設剩餘需求量，超庫存時阻擋並讓使用者改小或分次，不偷偷縮減；日期與「確認尚未登錄扣帳」勾選保留。最終確認列收藏、副本、產品、尺寸、張數、扣前後餘額與不可撤銷警語；庫存或版本變更須重新載入再確認，後端強制併發檢查。
- 有有效套用時鎖定核心需求欄位但可繼續套用剩餘量；第一版備註也鎖定。增量新增補充需求，不能當錯誤更正。
- **「不需要清點」收藏的停用原因文字**【已定稿】：「此收藏標示為不需要清點；套用需要組件已清點，請先改為需要清點並完成清點」。

**第一版限制**：無撤銷、需求備註鎖定、不能登錄已套用耗損；不得用手動交易宣稱更正了套用進度。第一版範圍：每包張數鎖定、正確的副本需求與封存排除、兩層不足、R08 各分頁與 R09 全域清單／套用／最後確認、移除手動 USE。

**後續獨立階段（規格已定稿，尚未實作）**：單筆整筆撤銷，原因（登錄錯誤、產品錯、副本錯、張數錯、其他且其他必填說明）；新增撤銷紀錄，不改刪原套用與 USE；退回或不退回無預選；退回原產品原張數，由系統建 RETURN 並關聯，手動不可偽造；撤銷與回補原子提交、防併發與重送，一筆只撤一次；重新套用是新紀錄；無有效套用才解鎖核心欄位；須明示不退回後重套會再次扣庫存。拆除與耗損另設計。

## 六、R10 採購、分攤與成本【已定稿，規格討論收尾】

**頁面與流程**：`/admin/purchases` 清單與新增／編輯／唯讀各為整頁，路由不變，不用抽屜，桌面與手機同流程。清單只放篩選、摘要、列表與「新增訂單」；唯讀整頁顯示原因、不提供儲存；返回保留篩選、排序、頁碼；只有有未存變更才提醒離開；儲存成功留在訂單頁並顯示訊息，新增成功轉成該筆編輯視圖。

**金額**：畫面標「金額（TWD）」等幣別，不統稱「元」；以主要貨幣單位輸入、整數最小單位儲存；用字串解析，不四捨五入；小數位數由明確設定決定，未知幣別不默認兩位。貼上接受千分位與貨幣符號但須驗證，符號與幣別衝突或逗號意義不明時要求修正。折扣與退款一律輸入正數，由欄位決定方向。精度、上限、換算由後端再驗。**已有非零金額禁止改幣別**，全部為零才可切換；幣別登錄錯誤的更正流程另議。當前以台幣為主。

**明細與收藏選擇**：用可搜尋選擇取代手輸 ID（與 R09 共用搜尋與顯示行為，各自設可選範圍；同名顯示收藏 ID、來源身份、版本）。封存收藏預設隱藏、可切換顯示、選取時警示：「此收藏已封存，本筆分攤仍會計入歷史採購成本，不會恢復收藏或增加持有副本數」；「封存」獨立標記，不取代已收藏／預購。收藏必填規則：**manual 可不指定**（標示「未指定收藏」，不自動猜歸屬、**不建立分攤列**），direct／weighted 必填；切換時有未指定明細須提示補選。運費稅費優先填共同費用。重複選同一收藏只提示不阻擋。說明選填；單價可為 0（免費品項）。明細新增在最後，第一版不提供排序（最大餘數法同餘數依輸入順序）；每單最多 30 筆，到上限即時提示。

**分攤**：

- 新操作只提供「手動」與「比例」分攤。direct 不是新建選項；既有 direct 訂單可查詢並保留標記，編輯重存前須明確選擇轉 manual（預填原分攤）或 weighted（顯示差異並確認），唯讀訂單不要求轉換。
- 比例分攤的基數是**淨支付**（商品金額＋運費＋稅費＋其他費用－訂單折扣－累計退款），按各明細淨額比例分配，尾數用最大餘數法。淨支付大於零但明細權重全零時禁止比例分攤，不自行平均；淨支付為零可全部分攤零。
- 只有手動分攤可編；切換方式時保留手動草稿並可撤回，最終確認才列出覆蓋影響。預覽完整顯示（淨支付拆解、每明細分攤、已分攤／未分攤、超額提示、尾數調整提示）。前後端共用完整算法；儲存時若結果與預覽不同，須重新預覽確認。
- manual 檢查：單筆不得為負、總和不得超過淨支付、未指定收藏明細不得有分攤額。

**退款**：訂單層單一「累計退款」，**取代目前總額、不是追加**，畫面並列原值與新值；不得使淨支付為負；允許調低以更正，但須確認。無修改歷史時不宣稱可查逐次退款。weighted 隨淨支付重算，儲存前預覽新舊對照，影響提示以去重後的收藏數計算（同收藏多列先合計）；manual 不靜默改值，淨支付低於手動分攤總和時阻擋。單項商品退款用手動分攤；不新增明細層退款欄位。說明文字：「累計退款作用於整張訂單，比例分攤依各明細淨額分配退款影響；若退款只屬特定商品，請改用手動分攤調整歸屬。」

**狀態與取消**：paid／partially_received／completed 計入收藏成本，open／cancelled 不計；到貨狀態是人工標記，不由副本或庫存推算。跨界確認依實際成本變化判斷（cancelled→open 只需恢復確認，不宣稱成本增加；paid→completed 無其他金額變更免確認），提示用去重收藏數、逐收藏差異與同幣別合計。取消是獨立操作：先處理未儲存變更再取消；只改狀態、保留當下分攤、不觸發 weighted 重算；不自動退款，提醒文字「取消不會自動登錄退款。若已實際退款，請先填累計退款」。已取消訂單整頁唯讀（備註也唯讀），只有明確的「恢復訂單」（須選目標狀態、不自動回前一狀態）；僅「已取消且無其他鎖定原因」才可恢復，後端強制；恢復到計入成本的狀態前須重新驗證並預覽。

**鎖定**：整頁唯讀，不做欄位級部分鎖定；原因並列（已取消與其他鎖定原因分開說明）；後端強制，不能只隱藏按鈕；鎖定優先於恢復，**取消也不能繞過鎖定**；鎖定訂單第一版只能查詢。第一版**不提供訂單刪除**（錯誤訂單以取消處理，限可編、未鎖定訂單）；已儲存明細不可移除，只能移除尚未儲存的新明細（後端禁止減少既有明細筆數且依明細順序更新，穩定明細 ID、引用檢查、成本影響確認須一起設計）。更正模型（幣別登錄錯誤、鎖定訂單）另階段設計，共用「保留原紀錄」原則但不直接套卡套反向交易。「無修改歷史」指沒有完整的使用者查閱功能，不代表刪除既有技術紀錄。

**清單**：桌面表格、手機卡片；欄位為日期、商店來源、訂單編號、狀態、幣別與訂單淨額、分攤情況、收藏（不同收藏數「等 N 項」，另顯示「未指定明細 N 筆」）、標記（鎖定／未計入成本／分攤不一致）、操作。預設全部狀態、日期新到舊（日期空白排最後，同日與同金額以 ID 倒序）；已取消淡化但文字須清楚；金額排序僅單一幣別，無效參數由後端處理。篩選：狀態、幣別、日期範圍、商店與編號文字搜尋（明確標示範圍，不含備註與明細說明）、收藏（可含已封存）、有未分攤（正餘額）、分攤不一致（含超額，不含合法 manual 未分完）、鎖定。篩選或排序變更回第一頁，返回恢復。第一版不加累計退款欄。

**摘要**（涵蓋完整篩選範圍、依幣別）：訂單淨額含 open、排除 cancelled，旁註「包含待處理訂單，非實際付款總額」；未分攤與超額分攤只計三種計入成本的狀態；訂單筆數含全部狀態，取消筆數是其子集；「取消訂單淨額」另列；收藏篩選時「訂單淨額」仍為整單，「此收藏分攤」只加該收藏，計入與未計入分開。

**成本呈現**：統一稱「已記錄採購成本」，固定說明「僅含已記錄的採購分攤，不含歷史價格與維修費，不等於收藏估值」；依幣別分列、不加總；無計入分攤顯示「尚未記錄」，合計為零才顯示 0。R02 清單一欄；R04 成本區兩段（貢獻成本訂單與依幣別合計；預設收合的「未計入成本的訂單」不納入合計）；訂單連結依權限開啟（可編輯進編輯視圖，鎖定才唯讀）。Dashboard 只加三張卡（已記錄採購成本、未分攤金額、待處理與已取消筆數），不加趨勢或排名；成本分「未封存收藏／已封存收藏」（預購、願望清單有有效分攤也計入未封存）；未分攤只加總正數餘額，超額分攤另標筆數與金額、不互相抵銷；不一致資料保留並警示，統計仍用已儲存分攤，受影響合計須標「含分攤不一致資料」並可連到相關訂單；未分攤卡連結保留幣別與計入成本狀態篩選。各頁共用資格與算法即可，不強迫同一條查詢。

**表單結構**：單頁分區 A 訂單資料、B 商品明細、C 費用與調整、D 分攤、E 私人備註（上限 3,000 附計數）；桌面右側固定預覽欄，手機底部固定摘要（超額或無法計算時優先顯示警示、不把負數寫成「未分攤」，不得遮鍵盤與錯誤）。手機明細由使用者自行收合。所有需確認的變更合併成**一個**最終確認步驟。儲存僅在可編輯且未送出時可按，送出中暫停重送、失敗保留輸入；驗證錯誤欄位旁加頁頂列出並可跳轉，驗證失敗時自動展開錯誤卡片。取消訂單放底部獨立區，有未儲存變更時停用並說明。新增預設：台北當天日期、TWD（須存在於已設定幣別）、比例分攤、open。

**小項**：商店來源自由輸入加既有值建議，不自動合併或改名；訂單編號重複以「同商店＋同編號」提示不阻擋（比對時去前後空白、忽略大小寫，儲存值保持原樣；排除正在編輯的自己、空編號不提示）；未來日期允許但提醒，訂單日期不等於預計到貨日，預購不自動填未來日期。

**入口與邊界**：R04 成本區提供「新增採購」，帶入第一筆收藏，其餘用預設；無效收藏明示錯誤；儲存後保留返回來源，來源參數只接受站內允許路徑。固定說明「儲存採購與分攤不會建立副本，也不會登錄卡套進貨」，但只能說「目前兩個新增流程不自動互建」——庫存交易資料表已有 `purchase_order_line_id` 欄位且採購鎖定會檢查此類引用，不能說資料模型無關聯。**R10 第一版限收藏相關採購**（不用未指定收藏明細登錄獨立的卡套、收納用品）。

**實作前核對後的範圍調整【已定稿】**：

1. R10 為採購訂單、明細、分攤唯一編輯入口；R03、R04 停止建立或修改採購，後端同步封閉繞道（現況：R03 價格非空含 0 即建單，R04 可建或更新管理訂單，皆預設 `admin_managed=0`，在 R10 出生即唯讀）。
2. 說明選填、manual 可未指定收藏且不建立分攤列；必要的 Migration 與圖形契約變更（資料庫 `description` 現為 NOT NULL 且去空白後長度須大於 0；分攤現須指定副本或收藏；編輯器鎖定現要求每列恰一分攤）納入第一版，先隔離驗證，正式執行另待批准。
3. 第一版只做收藏層成本，不提供單一副本成本；保留既有採購查詢把歷史副本分攤映射回收藏合計的讀取。
4. R03／R04 移除價格欄；R03 成功後提供帶入該收藏的「新增採購」連結。程式未發現 R02、R05、公開頁或報表顯示單副本成本。

**R10 實作前核對結果【現況】**：幣別小數位設定不存在（只驗三碼大寫）；單價只接受整數；取消／恢復無獨立操作、狀態可由通用儲存修改且無轉換規則、已取消訂單仍可改備註；鎖定判定為 `admin_managed != 1`、取得紀錄引用、庫存交易引用、或分攤圖形不符編輯器，無白話原因陣列；無採購刪除 API（資料庫非全面禁止 SQL 刪除）；有 `admin_revision` 比對與冪等鍵、同一 `db.batch` 原子儲存，真正同時請求未實測；公開資料用白名單。

**R10 驗收補充**：說明留空可存且不塞虛構文字；未指定收藏明細不建分攤列、重開不被誤判鎖定；weighted 與既有 direct 轉換仍阻擋未指定收藏；Migration 除空表外用合成舊資料驗證外鍵、索引、Trigger 與資料保留；R03／R04 舊請求不能再建改採購；並行編輯衝突時保留草稿、不靜默覆寫；冪等與原子性；後端繞過測試；公開資料邊界；移除未儲存明細後其他列與分攤不錯位。

## 七、R11 BGG／關聯／收藏組合（`/admin/bgg`）【已定稿】

**結構**：三個平行分頁「BGG 資料／遊戲關聯／收藏組合」，預設固定為 BGG 資料，分頁不加待處理角標。無參數直接開啟固定進 BGG 資料；從其他頁帶參數進入或返回原頁，恢復指定分頁與篩選、不強制跳回預設；各分頁保留自己的查詢狀態但不把不適用的篩選帶到另一分頁；跨頁連結帶指定條件時以連結為準。固定說明：

- BGG 資料：「查看並同步 BGG 遊戲資料；同步不會修改你的個人收藏紀錄。」（先不限定只更新快取）
- 遊戲關聯：「記錄遊戲之間的擴充、系列、整合遊玩等關係，與你是否擁有無關。」（不寫「版本」）
- 收藏組合：「記錄收藏紀錄之間的關係，例如組合包包含哪些收藏；不會合併收藏或副本。」

**BGG 資料分頁**：

- 「查看」（搜尋、篩選、展開證據）與「同步」分區；搜尋說明「搜尋只查本站現有資料，不會連線 BGG」（搜尋讀本站 D1 與靜態 JSON）。「同步」一詞只用於會呼叫 BGG 的操作，按鈕帶對象與數量與限制（每批最多 3 筆、間隔至少 2 秒）；第一版勾選上限 3 筆，超過或重複 ID 後端直接拒絕（不截斷、不排隊）。
- 逐列狀態：同步中、已同步、同步失敗、同步中斷、**尚無可確認的同步紀錄**（不叫「未同步」，靜態資料可能可用）；最後成功與最後嘗試時間分開，台北時區。失敗訊息白話化並保留原始碼；「已保留上次成功資料」只在確實有成功資料時顯示，首次失敗顯示「尚無成功同步資料」；自動重試資格與使用者手動再試分開，非暫時性錯誤（XML 格式、回應過大、認證未配置）不寫「再試一次」。
- 進度為批次層級（沒有逐列即時進度，API 整批完成才回結果）；進行中停用同步操作但保留唯讀查看，提示「同步正在進行或冷卻中，請稍後操作」；結果摘要區分成功、失敗、未完成；網路中斷未收到結果顯示「未能確認本批結果，請重新查詢」，不列精確筆數、不自動重送。
- 原始證據區稱「BGG 原始關聯證據（唯讀）」（顯示的是解析後證據）。
- **新 ID 入口**：獨立動作「新增 BGG 資料並同步」，固定說明會連線並新增本站資料列、不建立遊戲身份或收藏；已存在的 ID 改走一般同步；混合輸入時逐筆標示新增或同步；後端須防競爭重複；失敗留下的空列照實顯示且第一版不提供移除。
- 同步只更新 BGG 資料與同步控制／結果紀錄，關聯證據存於資料內容、不另寫關聯表。新 ID 同步成功不保證進入 R03 的 BGG 選單（讀靜態清單）或遊戲關聯選單（讀 `v2_games`）。
- **兩個身份標記（整輪提案，已定稿）**：「遊戲身份已登記／尚未登記」（依 `v2_games` 是否有該 BGG ID）與「本站候選目錄已收錄／尚未收錄」（依靜態可用目錄），兩者獨立於本次同步結果，查詢失敗顯示「無法判定」，已登記也不保證符合每個選擇器的角色資格。第一版不新增登記 BGG 身份的入口；固定說明不承諾去 R03／R15 就能建立身份（兩者仍受候選目錄限制），未收錄者第一版沒有一般登記入口；目錄來自本機遊戲與 JSON 快取，未找到定期更新排程，不承諾更新頻率。

**遊戲關聯分頁**：

- 關聯是遊戲身份之間的關係，不等於擁有。列表名稱優先、以關係句呈現，來源標籤與公開狀態分欄；公開狀態用「已確認可公開／未確認／已封存」，**不寫「已公開」**。確認效果說明：「確認後，此手動紀錄可供公開頁使用；實際顯示仍依遊戲的公開資格判定。」撤回確認提示：「此手動紀錄將不再供公開頁使用；同一對象的 BGG 證據或其他來源關聯可能仍會顯示。」（撤回不稱整段關係「下架」）。
- 方向句型：`compilation_of`＝合輯 A 包含遊戲 B；`requires_base`＝擴充 A 需要主遊戲 B 才能遊玩；`expansion_of`＝擴充指向主遊戲；`accessory_for`＝A 是適用於 B 的配件；`standalone_related`／`same_series`／`integrates_with` 按對稱處理；`other` 顯示「A 與 B 有其他關聯」，私人備註不能當公開說明。
- BGG 證據放在「查看某款遊戲」的唯讀區：顯示身份是否已登記、可否選用，加現有關聯清單（來源、類型、方向、狀態）；不能因兩款遊戲已有任一關聯就認定證據已建立對應，查詢失敗不當作尚無關聯；缺少身份的項目只顯示、不提供建立。「依此建立」只預填兩款遊戲，關係類型與方向由使用者自選，不依證據推定。
- 資料現況【現況】：`v2_game_relations` 來源允許 `bgg／manual／import`，R11 只建立、編輯、封存 manual；非手動來源的完整寫入來源待追查。
- 新增手動關聯預設未確認（允許當次直接勾選確認，但預設不勾）。表單：列表內展開，「〔遊戲 A〕〔類型〕〔遊戲 B〕」一句話排列並即時預覽，標籤隨類型調整（有方向的類型顯示角色，對稱類型顯示「遊戲 1／遊戲 2」）；搜尋選擇顯示名稱、BGG 或 NotBGG 標記；只列已登記遊戲身份；選項端點一次載入、本地搜尋，須有明確上限、不默默截斷，中英文名稱只用可靠現有資料、不假定雙語，提交時後端重驗資格（選項端點待實作）。
- 驗證訊息指出衝突對象（同一款遊戲、重複含對稱與已封存、循環帶有界路徑、端點不可用、「BGG 與 NotBGG 是同一款遊戲」、版本衝突）；對稱類型的 A–B 與 B–A 視為重複。結構化衝突訊息為實作項目（現況多數統一回 `RELATION_STATE_CHANGED`）。
- **核心欄位規則**：修改來源、目標或類型的同一次儲存，不允許同時保持已確認，須儲存後重新審視再明確確認；以「最後提交值與已儲存值是否不同」判斷（改了又改回不必撤確認）；前後端同步強制。只改備註或只改確認勾選不受影響。
- **封存與還原**：封存預設隱藏、整列唯讀；僅 manual 可還原，還原後一律未確認，不二次確認但須重新驗證端點、重複、方向、循環與版本並顯示結果；端點遊戲已封存則還原失敗並說明。封存確認文字：「封存後可還原；還原後需重新確認才可供公開頁使用」。還原採「還原原紀錄」，不放寬唯一約束（資料庫唯一約束含封存，封存後重建會被擋）。
- 資料庫對稱配對防護納入第一版（先隔離驗證，尚未證明既有程式可被併發繞過，不稱已確認漏洞）。遊戲身份沒有 production／test 範圍；封存的 NotBGG 身份不可新選，已確認同一身份的 BGG／NotBGG 不能互連。

## 九、整輪提案：「不需要清點」收藏欄位【已定稿，Migration 待批准】

- 新增明確持久欄位（Migration，先隔離驗證，正式執行另待批准）；既有收藏預設「需要清點」，**不推論回填**，36 筆組合包不批次改值，須逐筆由使用者確認；新增純容器（R03）預設「不需要清點」，其他類型預設「需要清點」；R04 可改，R02／R04 顯示與篩選。

- 不需清點不等於已清點，沿用既定規則 R09 不允許新增套用（停用原因文字見第五節）；既有需求、套用與扣帳保留，不能切換後假裝歸零。
- 程式目前尚未具備已定稿的完整紅灰計數服務，影響範圍須與 20 項清單一起核對，不能宣稱現況會正確排除。核對 P08 的結果是未找到明確儲存契約，也未證明所有歷史備註完全無資料——不得用「無副本／無組件」或備註文字推論。

## 十二、驗收原則

- 所有案例預設「待執行」，不寫成已通過；不得用手動交易宣稱更正套用進度；不得把未檢查的程式能力寫成現有能力。
- 每項完成須記錄：檔案、案例、隔離資料情境、命令、日期、結果與限制。
- 後端繞過測試必須涵蓋：直接呼叫 API 仍受精度、鎖定、狀態、分攤、資格與唯一限制。
- 併發與重送：真正的同時請求須實測；僅靠既有版本比對與冪等測試，不等於完成併發驗收。
- 公開資料邊界：私人價格、備註、訂單、操作人、editorNotes 不得進入公開頁或公開 API。
- 開發測試必列（卡套）：每副本展開、所有狀態與封存過濾、無交易與零庫存、無產品與全停用、完整篩選摘要與分頁、兩收藏 80/80 對庫存 100、多產品 60/60 分次套 100、鎖定與重啟、未知影響範圍、資格失敗原因、最後確認過期、併發負庫存、原子套用與重送防重、交易完整帳餘額、API 禁手動 USE；後續再測遷移保歷史、撤銷可選回補、重扣提示、防雙回補、需求解鎖與所有公開／管理統計。
