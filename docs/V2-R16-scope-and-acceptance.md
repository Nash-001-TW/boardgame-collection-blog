# R16 第一版範圍與驗收

2026-11-17。議題1～3已採納，本次整理草案；本輪補充／修正待使用者採納，不代表已實作或測試通過。未改功能、執行Migration、寫正式資料或部署。

## 第一版範圍

- /admin/notbgg/[id]/relations，「適用遊戲（配件關聯）」，固定來源名稱ID。R12/R14配件入口與R11唯讀列；安全白名單返回，指定relation id核實來源並定位，歷史列自動顯示，無列明示。
- 非配件或封存來源顯原因連R14；已封存全頁唯讀，後端新增／封存拒絕，含以此新增。
- R16唯一site寫入入口。R14專用／相容唯讀摘要與連結；R13成功連R16。省略relatedGameIds保留資料可存其他欄；企圖修改明確拒絕，不用[]預設清空。保原稿建立原子性、歷史讀取與type有效關聯阻擋。
- 展開新增一句話，專用預設，角色預覽；專用非排他，相容非系統判斷；配件→遊戲不對稱。共用R11身份選項互動端點（尚待實作），不選cache空列、自己、封存NotBGG、已確認同身份別名。
- 目標限遊戲／擴充含standalone，不配件。**未知或矛盾須先修正／釐清權威型別才可新增，不以使用者勾選繞過**。此為本輪對未知提案的修正，待採納；UI說明而後端同驗。
- 完全相同有效關係阻擋連既有，跨表相同manual accessory亦阻擋；不同類型可並存只提示。私人備註3000、建立後不可改，無update/delete/restore。以此新增只預填重驗、不保證可重建。
- busy與後端冪等同鍵同內容回原結果、不同內容拒絕；不同請求撞既有不當作備註已存。新增＋事件原子，封存同樣原子與併發資格檢查。
- 桌表手機卡，預設有效可含封存；完整來源有效N／封存M，來源與目標封存分開；有效先時間降序ID穩定。詳情只真實備註／時間／操作者，不每列標公開。R11關係收合唯讀含方向狀態連回，不含整份證據。
- 第一版不做分頁，但查詢／回應仍有界；到上限明示無法完整載入，不靜默截斷、假完整或假無衝突，門檻與擴充方案實作時列清。此有界補充待採納。
- 封存確認句與備註摘要，成功不可還原。合法重送已封存無害且無第二事件，但已封存來源拒絕優先。封存無原因欄，本版不新增。
- 無公開確認步驟，可能從配件或適用遊戲一側呈現，依該頁及身份解析資格；封存排除此筆候選但其他來源仍可顯，notes／操作紀錄私密。

## 範圍與契約更正

跨表一致性是**R11／R16共用重複服務＋DB防護**；R13/R14不再是第三個關係寫入服務。它們的關係修改payload回不可從此修改，無須裝成與重複相同錯誤。測試需確認不能繞道、不是三邊都跑相同新增。

「類型未知顯示提示」不是資格豁免。尚未設計人工覆寫資料型別與稽核流程，不本輪暗加。

不分頁不等於無上限查詢；不顯每列公開狀態不等於不驗公開邊界。封存不記原因，但已有事件操作者／occurred_at保留。

## 待核與實作差異

來源封存後端拒絕、archive重送無害（目前NOT_FOUND）、冪等及原子重驗、目標型別與已確認同身份、來源／目標變更競爭、跨表共用、新身份選項、列定位、事件操作者JOIN（避免多事件放大筆數）均需實作驗證。

有效unique(source,target,type)忽略封存、notes DB不可變／API3000、site無確認旗標已核。正式site0、配件目標0只是2026-11-17快照。公開site archived_at排除已核，但不同公開投影與快取失效仍須測，不承諾瞬間全網移除。
