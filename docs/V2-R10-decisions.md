## 議題 4：本輪程式核對（不是新規格批准）

來源 src/lib/purchase-admin.ts、src/lib/purchase-admin-controller.ts。

- weighted 使用商品淨額加運稅費減訂單折扣與累計退款的淨支付總額，按各列商品淨額分配。
- direct **不會**自動套明細淨額；和 manual 一樣讀取提交的各列 allocated 值，只是儲存的 allocation_method 不同。
- 最大餘數法同餘數按輸入明細 index，讀取明細按 line_number。相同輸入順序可重現，但重排會改尾數歸屬。
- 分攤實際寫入 v2_purchase_allocations；可編輯訂單重存時原子替換編輯器管理的分攤，weighted 依新淨支付重算，direct/manual 仍用送入數字。
- 後端要求非負安全整數，分攤和不得超淨支付；淨支付不得負。weighted 所有權重為零時拒絕。
- 前端只預覽總額與未分攤，沒有共用完整逐列最大餘數預覽。
- 此次順帶發現與議題3新規格差異：現行 API 強制每列 collectionId 正整數、description 非空，寫入限 production 未封存收藏。需後續改後端，不是只換元件。

## 議題 4：建議已由使用者採納（後續 direct 處理見下節）

- weighted 淨支付為總額、manual 可編、切換覆蓋確認、轉 manual 預填現算值、預覽完整拆解與分攤餘額尾數提示。
- 不採 direct 自動分明細淨額：折扣／退款可能讓明細淨額和大於淨支付，違反上限。建議先移除 direct 新增選項，保留歷史查詢，僅 manual／weighted；若要保留 direct，需先定義獨立業務語意，不更寫歷史。
- 明確處理淨支付零與全零權重；正淨支付且權重全零不可比例分攤，不平均猜分。尾數用穩定明細順序，前後端同算；預覽與提交條件變更須重新確認。
- 以上需獨立驗收金額精度／溢位、共同費用／折扣／退款、零權重、同餘數排序、方式切換、分攤超額負值、原子重算與歷史唯讀；均待測。

## 議題 5 與 direct 邊界：已採用

- 新操作只 manual／weighted；歷史 direct 保留原標記，唯讀無須轉換。可編訂單重存須明選 manual（預填原值）或 weighted（差異確認），不靜默轉換。

## 議題 6：已由使用者採納

- paid／partially_received／completed 計成本；open／cancelled 不計。此集合已讀到 purchase-admin.ts 成本查詢，但收藏頁／Dashboard 是否一致尚待核對。
- 到貨狀態人工標記，不連動副本／庫存。跨計成本邊界確認去重收藏數、逐收藏與同幣別合計變化；cancelled→open 沒有成本跨界但仍需恢復確認，paid→completed 無其他金額變更不額外確認。
- cancelled 整頁唯讀＋恢復動作，恢復明選目標，不推前狀態；原有歷史／外部引用鎖定優先，不能因恢復繞過。備註亦唯讀。
- 取消保留明細、分攤、退款、不自動退款，保留取消當下分攤而非藉取消重算。取消當獨立狀態操作，先處理未儲存金額／明細變更，不能用取消保存不一致資料。恢復計入成本前驗分攤與淨額及預覽。
- 取消排除一般有效訂單支出合計，但另列取消筆數與取消訂單淨額（同幣別分開），標示非實際現金流證明，不將取消當作已退款。退款提示：取消不會自動登錄退款，若已實際退款請先填累計退款。
- 待查：前狀態／時間、轉換限制與 cancelled 編輯、各摘要狀態條件、封存收藏連動；精確後端及全頁一致性未驗證。
- 待測：所有成本跨界、恢復至 open／計入狀態、外部鎖定不可繞過、取消不回補或清除資料、取消不重算、保留退款與成本正確排除、取消淨額仍可查、併發／過期預覽與原子狀態操作。

## 議題 7：已由使用者採納

- 歷史／外部引用整頁唯讀，多原因白話並列，取消原因與其他鎖定分開；沒有其他鎖定的已取消訂單才可恢復。後端強制只有 cancelled 可恢復、其他鎖定不可恢復或取消；第一版不開備註例外。
- 第一版不提供刪除或鎖定繞道。幣別錯誤及鎖定訂單更正列後續設計，保留原紀錄但不直接套用卡套反向交易模型。
- 收藏成本區可達貢獻成本訂單，封存收藏同樣可查；收藏篩選並列訂單淨額／此收藏分攤／是否計入成本，不相加。open/cancelled 保存分攤不代表計入成本。
- 待核：精確歷史／外部引用鎖定條件及 API 強制、刪除端點／關聯處理、收藏頁與封存連結、歷史價格有無重加。現況不能推定已符合。

## 議題 8：已由使用者採納

- 固定稱已記錄採購成本，說明僅採購分攤、不含歷史價格維修費、不等於估值；依幣別代碼分列，無有效分攤為尚未記錄，有有效分攤合計零才為幣別0。
- R02 只呈合計；R04 有效成本與貢獻訂單在上，open/cancelled 訂單收合在下。訂單連結依訂單權限可編／唯讀，不把所有訂單強制唯讀。封存收藏成本仍可查。
- Dashboard 三卡：已記錄採購成本（目前未封存／已封存收藏分列）、未分攤金額、待處理／取消筆數分列。此處目前收藏指未封存紀錄，不以 owned 狀態或在藏副本數過濾，避免願望／預購歷史分攤消失；需標名清楚。
- 未分攤只加計成本狀態訂單的正數餘額，可連有未分攤篩選並保留狀態與幣別。負餘額列超額分攤警示與筆數／金額，不抵銷其他訂單正數餘額；取消淨額仍須在訂單清單摘要依幣別可見。
- 異常資料保留已儲存分攤、不靜默修正，但受影響合計標示含分攤不一致資料並提供訂單入口，不能只在訂單頁警示。manual 未分完是允許狀態，不等同分攤不一致。
- 共用成本資格與金額定義，允許列表／詳細／Dashboard 用不同聚合形狀的查詢；不要求將全部明細載入每頁。只做三卡，無趨勢／排名／匯兌估值。
- 待核：各頁來源與幣別分布、完整對帳餘額是否可直接算、有未分攤篩選、不一致及願望／封存關聯聚合筆數。未查正式資料、不批次修改。測試零與無、封存分類、多幣別、不重扣退款、正負餘額不互抵、異常警示與分頁統計一致。

## 議題 9：已由使用者採納

- 桌面欄：日期商店編號、狀態、幣別訂單淨額、已分攤／未分攤或超額、前1～2個收藏名稱與不同收藏總數、未指定明細筆數、鎖定／未計入成本／不一致標記、依權限開編輯／唯讀。手機簡化日期商店狀態淨額標記，其餘進明細。取消淡化但維持可讀，不只靠顏色。

- 收藏篩選整單淨額與此收藏分攤兩區不相加，該收藏計入／未計入分列。有未分攤＝正餘額；不一致不含合法manual未分完。

- 單頁A訂單資料、B商品明細、C費用退款、D分攤、E私人備註3000字計數；無分步精靈。頁首先返回標題狀態，唯讀原因並列。
- 桌面sticky預覽須可捲且不遮內容；手機固定列顯淨支付／未分攤，異常優先顯警示而非負數未分攤。展開完整預覽可關閉，鍵盤／焦點／錯誤欄位不被遮擋，頁面保留底部空間。
- 新增明細在末、不拖曳排序；手機明細由使用者收合、不在輸入完成時自動折起；有錯誤卡片自動展開並定位。既有儲存明細能否移除尚待設計與後端核對，不因卡片操作默認可刪。
- 可編表單儲存於未通過驗證時仍可按，顯欄位錯誤與頁頂可跳摘要；送出中暫禁重送、顯進度，失敗恢復且保留資料。唯讀不提供儲存。後端冪等／併發仍必須實作。
- 狀態成本影響、退款前後、分攤覆蓋與新舊值合併一次最終確認；編輯尚未儲存時取消操作禁用並說明，取消獨立區，無鎖定才提供。方式切換若將覆蓋未存手動值，切換當下先保留草稿／提供撤回，不能等最終確認前已丟值。
- 新增預設今天（Asia/Taipei）、TWD（須已設定）、weighted、open；幣別與日期可改，預設open不計成本。全零明細權重按議題4處理，不能預設weighted後自動猜平均。
- 待核：元件互動與共用算法、精度設定、單價0／數量及明細上限、髒資料偵測、錯誤回傳。既讀API單價允許0、數量1～10000、明細1～30，但前端一致性與歷史資料未驗證。
