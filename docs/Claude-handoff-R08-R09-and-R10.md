# 給 Claude：R08／R09 規格交接與 R10 討論起點

日期：2026-11-17（Asia/Taipei）。本文件可單獨上傳給 Claude，不需要讀取本機連結才能理解。

## 給接手 Claude 的任務

請以本文件為上下文，繼續與使用者討論 **R10 採購、分攤與成本**。先提出 R10 第一個設計議題與具體建議，逐項取得確認；將問題分成「使用者可決定的設計」與「需 Codex 查程式／資料的事項」。不要重新詢問已定稿的 R08／R09 規則，不把待確認事項當成使用者批准，不直接實作或部署。若無法存取程式，請列核對問題，勿自行推定答案。

本輪只完成規格討論與文件，**不是功能已實作或測試通過**。正式基準是 2026-11-12 Release-03 version 19：建置、限定公開與管理員唯讀／登入驗收通過；不為重確認而要求再次登入。原 UI 審核圖為合成資料預覽，不是正式資料截圖。功能驗收也不代表所有頁面設計獲准。

## 一、名詞與跨頁規則（已採用）

- R02 收藏清單、R04 編輯收藏、R05 副本、R06 實體組件與清點、R07 組件分類證據、R08 卡套管理、R09 卡套需求與逐副本套用、R10 採購、R11 BGG／關聯／收藏組合。
- 庫存按**產品**記帳，需求與扣帳以**張**計；尺寸是彙總維度。產品與需求各自引用獨立尺寸資料表。
- 建立需求／指派組件不扣庫存；確認套用同時建立負數 USE 交易與套用紀錄，沒有「已套用待扣帳」狀態。
- 在藏、借出計入持有副本數與需求；借出不能清點或套用，保留清點結果，未清點仍列 R06 待確認並說明「借出中，歸還後才能清點」。
- 售出、送出、遺失排除目前數量／清點與缺件提醒／待套用需求，於 R05「不在藏副本」收合，問題與歷史保留。
- 未知不納入已確認持有數或確定需求，獨立稱「狀態未知」、提示可能漏計，不混入 R06「待確認」角標。
- 收藏封存優先，其副本全部退出目前數量與需求。狀態變更／封存不刪關聯、不回補卡套；歷史成本、交易、使用保留。
- 至少一副本且全為售出／送出／遺失才提示「所有副本均已不在藏」，不自動改收藏狀態。零副本／含未知不適用。
- 語言差異可用副本區分；組件／卡套需求結構不同則分收藏紀錄，新增同款只提示不強制合併。

## 二、R08 產品分頁（已採用）

桌面表格、手機卡片；欄位為品牌名稱、寬高 mm／厚度／每包張數、帳面餘額、啟停狀態、經算法驗證才提供的套用筆數；操作為編輯、登錄進貨、停用。新增／編輯採列表內展開區。

- 列表與摘要只顯示張，包與換算放交易輸入；交易歷史保留原包數與每包張數快照。
- 無交易顯示「尚未建立」，不是 0；明確零餘額才顯示 0 張。異常負數警示。
- 摘要涵蓋完整篩選範圍，不限當頁，分列啟用庫存與停用產品另有庫存；不完整時稱「已知庫存合計」並提示未建立庫存的產品數。
- 預設啟用，能切換停用；搜尋品牌名稱、尺寸下拉，不輸入 ID。
- 新增不直接輸入庫存；儲存後可跳交易登錄。重複品牌名稱尺寸提示、不阻擋，提供使用既有產品；不同進貨批次優先沿用產品新增交易。
- 有交易或套用歷史後尺寸與每包張數鎖定，說明引用數；品牌名稱備註可改。更正尺寸停用舊產品、新增正確產品。厚度未提供不顯示 0；厚度編輯限制未另定。
- 停用須二次確認，明示不可再套用、餘量不計可用、歷史保留；可重新啟用但不解除歷史鎖定。停售且仍要用餘量時不應停用。

## 三、需求與不足算法（已採用）

需求量為**每個適用副本各需要 N 張**；未指定副本則按符合狀態的副本展開，指定則僅該副本。每副本每需求待套用量＝需求量－有效已套用量，再按尺寸加總。只計在藏／借出，排除封存；未知提示可能漏計，歷史無法判定不能當正常零。

啟用庫存＝該尺寸啟用產品的帳面餘額合計，不再扣已套用量。

- **全域**缺口＝max(0，全域待套用量－啟用庫存)。Dashboard：「N 種尺寸庫存不足」。
- **收藏**：該收藏某尺寸待套用量超過同尺寸啟用庫存則計 1 項，同尺寸不重複；R02／R04：「卡套不足 N 項」。不預留／分配庫存，不能相加當全域結果。
- 例：兩收藏各需 80、庫存 100，各收藏 0 項，全域缺口 60。
- 可分次用不同產品：A/B 各 60 可分次滿足 100；每次只須所選產品足夠，總套用不超需求。程式支持累計上限，實作前仍須實測驗證此情境。
- 不新增卡套「待確認」統計來源。詳細原因於 R09 資訊提示；受影響數值不能寫充足／0，可為「—」或已知量加可能漏計。R08 可展開資料不完整原因，不新增角標。

## 四、R08 尺寸與庫存分頁（已採用）

一列一尺寸：寬高、啟用產品數、已知庫存、未套用總需求、缺口（不足 N 張／充足／無需求／—）、有效需求筆數與歷史套用筆數。筆數不是張數，也不是使用交易筆數。

- 展開各產品餘額、需求收藏／副本與 R09 連結、停用庫存。
- 無任何產品但有需求：資料不完整，庫存／缺口「—」，不計不足數，提供帶尺寸新增產品入口。
- 有產品但全停用：啟用可用庫存 0，需求完整且大於 0 時計不足，另列停用庫存。
- 僅相關尺寸受不完整影響；無法定位影響尺寸另列資訊提示，不能假裝其影響已知。
- 排序：確定不足、資料不完整、其餘依尺寸。篩選只看不足／有需求／尺寸；有需求包含可能有需求但無法完整計算者。
- 固定說明：「尺寸合計僅供概況；每次套用須選一項產品，且該產品庫存須足夠。可分次使用不同產品。」

## 五、R08 庫存交易分頁（已定稿）

列表：交易日期、產品品牌名稱尺寸、操作、帶正負方向的張數（原包數／快照為補充）、交易後餘額、原因備註、可實際抵達的關聯。桌面表格／手機卡片。篩選產品、尺寸、類型、日期範圍。

- 預設入帳順序最新在前，可依交易日期排序；餘額仍按完整產品帳的實際入帳順序計算或可靠保存，篩選／分頁／日期排序不能重算其定義。
- 手動產品可搜尋並顯示尺寸、日期預設今天、原因必填，預覽新餘額，後端及 DB 阻擋負庫存。
- 目標支持包／張換算，例如 3 包＝300 張；目前僅進貨按包、其他按張，通用切換的後端與快照限制仍需設計／驗證。
- 類型：OPENING_BALANCE 期初、PURCHASE 進貨為增加；USE 使用、DISCARD 報廢為減少；RETURN 退回增加；ADJUST 調整可正負。
- 第一版移除手動 USE，UI 與 API 都限制；USE 只由 R09 套用產生。舊手動 USE 保留，不偽造套用關聯。
- 手動退回與報廢原因必填。報廢僅扣仍在庫存的卡套；已套用扣帳後損壞不能再報廢扣一次，第一版無法登錄已套用卡套耗損。
- 交易不可編刪、更正新增反向調整是最終規則；第一版不提供編刪。**全面 DB 不可變限制與更正關聯欄位延至後續遷移階段**，不能說第一版已全面強制。

## 六、R09 入口、收藏內容與套用（已採用）

- 選單入口預設有待套用需求收藏清單，不是空白搜尋頁；順序為不足收藏、資料不完整收藏、其餘有需求收藏。不能只篩確定量大於 0 而藏起未知資料。可搜尋零需求收藏以新增需求。
- 從全域清單或 R04 卡套需求分頁進入同一收藏內容元件，用可搜尋收藏選擇取代手輸 ID。
- 頂部：不足項數、完整或明示不完整的待套用張數、歷史未對應／未知副本提示；可提示此尺寸與其他收藏合計超庫存，不計角標。
- 需求卡：尺寸、每副本需求量、全部／指定副本、組件、進度彙總、鎖定原因；副本列有狀態、組件清點、進度、產品張數日期歷史、套用操作。
- 資格：有效實體 card 及簽章版本證據、該副本該組件已 checked、在藏未封膜、收藏未封存、同尺寸啟用產品且庫存足夠、未超需求、沒有阻擋的未對應歷史。副本整體清點不能取代組件清點。
- 停用操作時明示未清點／借出／未知／資格不符／產品或庫存問題等原因，不僅變灰。
- 套用選同尺寸啟用產品並顯示餘額；預設剩餘需求量，超庫存時阻擋並讓使用者改小或分次，不偷偷縮減；日期及確認尚未登錄扣帳勾選保留，防止舊手動扣帳再扣一次。
- 最終確認列收藏、副本、產品、尺寸、張數、扣前後餘額、不可撤銷警語。庫存／版本變更須重新載入再確認，後端強制併發檢查。
- 有有效套用時鎖定核心需求欄位但可繼續套用剩餘量；第一版備註也鎖定。增量新增補充需求，不能當錯誤更正。

## 七、需求表單：最後一輪建議尚待使用者明確確認

不要把本節寫成已批准：

- 每適用副本 N 張，預覽 N × M＝T；預設全部在藏／借出，可指定。全部是動態範圍，將來符合資格的新副本也納入；未知提示漏計。
- 尺寸用既有選單，**包含無產品的歷史尺寸**；全新尺寸經 R08 建產品，不在需求自由輸入。這是 Codex 對 A 的調整，使用者尚未回覆。
- 寬高為 0.1 mm 整數、組合唯一；63 與 63.5 mm 可能是真實差異，不近似自動合併。
- 搜尋尺寸並標產品狀態；跳新增產品後返回保留表單。只提供合格新指派組件；歷史不合格引用保留辨識不自動清空。無合格組件連 R07 證據／R06 管理。
- 名稱／說明目前同一 notes 欄，上限 1,000；是否強制組件必填未決，現況允許未指派。

## 八、後續獨立階段與已知限制

第一版：每包張數鎖定、正確副本需求／封存排除、兩層不足、R08 各分頁與 R09 全域清單／套用／最後確認、移除手動 USE。

第一版限制：無撤銷、需求備註鎖定、不能登錄已套用耗損。不得用手動交易宣稱更正了套用進度。

後續：撤銷、更正交易關聯、全面不可變、備註解鎖及修改歷史；拆除／耗損另設計。

撤銷規格已定稿：單筆整筆撤銷，原因（登錄錯誤／產品錯／副本錯／張數錯／其他，其他必填說明）。新增撤銷紀錄，不改刪原套用與 USE。退回／不退回無預選；退回原產品原張數，由系統建 RETURN 並關聯，手動不可偽造。撤銷與可選回補原子提交、防併發／重送，一筆只撤一次不可取消；重新套用是新紀錄。無有效套用才解鎖核心欄位，各處進度與不足依有效套用重算。須明示不退回後重套會再次扣庫存；已手動退回請選不退回，系統無法自動辨識舊無關聯退回。歷史未對應造成整收藏鎖定另案處理。

## 九、未決與測試交接

未決：封存收藏／已退出需求的歷史套用在哪裡可達（R09 唯讀或其他歷史入口）；不可讓歷史筆數成死連結。最後一輪需求表單建議尚待確認。原 R08 審核還包含「需求查詢」分頁，其獨立保留或與 R09 整合未定，不可自行刪除。

待查：副本所有新增／轉換途徑預設（核心 Schema 為 in_collection，不代表所有途徑）、正式各狀態筆數／unknown 建立時間來源、歷史手動 USE、產品品牌厚度必填、全域資料來源與完整性判定、套用筆數算法、停用產品手動帳務規則。大量未知要先規劃整理，不猜測批次改值。R01～R07 的 20 項及 R06 上線前六項仍待取得原清單核對，不能標完成。

開發測試必列：每副本展開、所有狀態／封存過濾、無交易與零庫存、無產品與全停用、完整篩選摘要／分頁、兩收藏 80/80 對庫存100、多產品60/60分次套100、鎖定與重啟、未知影響範圍、資格失敗原因、最終確認過期、併發負庫存、原子套用與重送防重、交易完整帳餘額、API 禁手動USE。後續再測遷移保歷史、撤銷可選回補／重扣提示／防雙回補、需求解鎖與所有公開／管理統計。

全部是待執行，不是測試證據。每項完成需記檔案、案例、隔離資料情境、命令、日期與結果。不得自行在正式庫造測試資料或要求貼秘密。

## 十、R10 接續背景：已讀程式／審核現況，尚非新設計定稿

路由 /admin/purchases；?new=1 新增、?id=<id> 編輯。同頁表單下方仍有篩選、摘要與清單，手機較長。

- 訂單欄位：日期、商店來源、編號、幣別、狀態、運費／稅費／其他費用／訂單折扣／累計退款、分攤方式、私人備註（3,000）。
- 明細：收藏、說明、數量、單價、本項折扣、分攤額。現況有手輸收藏 ID，後續可討論搜尋選擇。
- 狀態：open、paid、partially_received、completed、cancelled。分攤：manual 可保留未分攤、direct、weighted 按明細淨額，以最大餘數法分配尾數。
- 商品金額＝各明細數量×單價－本項折扣之和；淨支付再加共同費用、減訂單折扣與退款。金額目前以整數最小貨幣單位輸入（如 TWD 分），不是直接輸入元。
- 不換匯、不跨幣別加總、不把歷史價格或維修費另加成成本；已記錄成本不等於完整收藏估值。
- 待處理與取消訂單不列已付款收藏成本；收藏篩選下訂單支出仍為整筆訂單，收藏成本僅其分攤。此為現有畫面說明，精確狀態／查詢算法變更前仍須查後端。
- 歷史／外部引用訂單唯讀，精確鎖定條件須查後端，不假定都能編。儲存採購與分攤不建立副本，不應假定會自動建立卡套進貨。
- 已封存收藏歷史成本保留；不能將卡套帳務的不可變規則直接套成「所有採購都不可編」，R10 是獨立業務待討論。

建議 Claude 的第一輪：簡短確認接手後，從「R10 清單與新增／編輯是否分開顯示」提出建議，再逐步談金額輸入（元顯示與最小單位儲存）、訂單明細與收藏搜尋、分攤預覽、退款／取消及唯讀歷史。每輪聚焦一個決策；需要精確後端事實就列給 Codex 核對，不先擴大實作範圍。
