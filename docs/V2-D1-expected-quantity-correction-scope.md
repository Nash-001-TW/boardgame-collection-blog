# D1 第一版｜共用預期數量更正

2026-11-19（台北）。採方案 A，依本次「確認此方案並進入規格整理」記錄。本文定義業務範圍與驗收，尚未實作或執行驗收。

## 適用範圍

- 更正對象為收藏共用的實體組件定義。保留 S4-A，逐副本與版本專屬預期量仍待另議。
- 管理員須確認可信勘誤適用於整個共用定義的適用範圍，才可更正。共用值也影響日後繼承該定義的副本。現有副本全選、相同語言或版本文字，都不能單獨證明公告涵蓋整個範圍。
- 公告只涵蓋部分版本、版本不明或依據不足時，保留原預期量與勘誤證據。可核對且對應版本的原廠／發行方勘誤優先。單盒的實物證據可支持調查，不能推定共用預期量。證據保存的邏輯設計見下節，儲存方式仍待決。
- 更正保留各副本實點、原清點日期、checked 與完成狀態。實點超過預期時保留實點並顯示差額。單純更正預期量不產生清點事件或適用性導致的完成轉換。
- 更正後須能追溯前後預期量、勘誤來源、適用範圍與更正時間，並還原當時依據及判讀。逐盒快照或可重建歷史留待儲存設計。

## 驗收矩陣

| 案例 | 初始條件與操作 | 預期結果 |
| --- | --- | --- |
| D1-01 全範圍勘誤 | 共用預期 103，實點 99 且已 checked；有可信勘誤且管理員確認涵蓋整個共用範圍 | 共用預期改為 100，實點仍為 99；可回溯先前少 4 張、目前少 1 張。原清點日期、checked 與完成狀態保留。 |
| D1-02 部分版本 | 公告只涵蓋英文初版，另一版本仍應有 103 | 共用預期維持 103，其他版本不受影響。不寫逐盒或版本例外。保留勘誤證據與部分涵蓋的理由。 |
| D1-03 資訊不足 | 某些副本版本不明，或只以相同語言／版本文字及全選現有副本作為依據 | 拒絕更正；保留原預期量與各盒實點。 |
| D1-04 超出預期 | 實點 103，合法更正預期量至 100 | 顯示多於預期 3 張，保留實點 103、原清點日期、checked 與完成狀態。 |
| D1-05 歷史回溯 | 查閱 D1-01 更正前後紀錄 | 能還原 103／99 → 少 4，以及 100／99 → 少 1；可追到更正依據、範圍與時間，原清點事件可辨識。 |

## 勘誤證據保存｜設計審查稿

依本次「確認選擇，進入規格設計審查」，第一版採證據保存方案 A。可以先登記尚未確認範圍的公告，也保留已套用及確認不適用的證據。以下是供審查的邏輯契約，欄位與狀態細節待審。

一份公告可能提及不同組件或版本。公告保存來源與原始內容，審查狀態以「公告 × 目標共用定義」為單位。實際更正另有紀錄，關聯公告與目標。一次套用到某個定義，不會把同一公告對其他定義的審查一併標為已套用。

| 審查狀態 | 條件 | 對共用預期量的影響 |
| --- | --- | --- |
| `PENDING` | 新登記、適用範圍待核、依據不足，或已確認整個範圍適用但尚未提交更正。記錄停留理由。 | 保留原值。 |
| `NOT_APPLICABLE` | 確認公告不能套用到目前的整個共用範圍。理由可描述完全不適用或只涵蓋部分版本，部分涵蓋仍可供後續調查。 | 保留原值。 |
| `APPLIED` | 管理員確認公告涵蓋整個共用範圍，且更正成功提交並有對應紀錄。 | 使用更正後共用值。 |

### 最小邏輯資訊

| 紀錄 | 資訊 |
| --- | --- |
| 公告證據 | 來源名稱、網址或附件參照、公告日期（未知可留空）、取得時間、原始說法及勘誤內容、公告所述版本條件。保留原始依據供回溯。 |
| 目標審查 | 目標共用定義、審查結果與理由、所採信的版本及適用範圍、認證操作者與審查時間。 |
| 實際更正 | 關聯公告及目標、原預期量、新預期量、提交時確認的範圍、認證操作者及套用時間。能回溯原清點所用依據與判讀。 |

只有實際更正提交成功才成立 `APPLIED`。共用預期值與更正紀錄應一致提交。若已知提交失敗，維持先前值及審查狀態；若結果未知，先核對原操作結果，再決定是否重試。相同操作重送不得形成第二筆更正。若目標預期量或適用範圍在確認後已變動，拒絕過期提交並要求重新核對。
